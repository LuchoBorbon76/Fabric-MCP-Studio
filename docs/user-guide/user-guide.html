What Fabric MCP Studio does

Fabric MCP Studio is an app that runs on your own computer and opens in your web browser. It helps you build an analytics solution in Microsoft Fabric – your organization's data platform – without writing code.

Think of it as a guided assembly line. Each station builds on the one before:

1. DataBring in sample data, your databases or data already in Fabric
2. Semantic modelOne trusted set of numbers: tables, relationships and business measures
3. ReportsProfessional Power BI reports – even maps – built for you
4. Answers & sharingAsk questions in plain language; share in Teams and Microsoft 365 Copilot

You can do every step in two ways:

  • Click the buttons. Every page has clear actions such as Load sample, Create semantic model or Build report.
  • Ask Copilot. Type what you want in plain language, for example "Recommend the best report for my data". Copilot explains its plan and asks for your approval before it changes anything.
It works as you. The app signs in to Microsoft Fabric with your own work account, so it can only see and change what you are allowed to. Everything it builds lives in your organization's Fabric, not on your computer.

Install the app (one time)

A. Install Node.js

  1. Open your browser and go to nodejs.org.
  2. Select the big download button marked LTS (Long Term Support). Version 20 or newer is fine.
  3. Open the downloaded file (it ends in .msi).
  4. Select Next on every screen, accept the license, and select Install. Keep all default options. You can leave the "Tools for native modules" box unticked.
  5. Select Finish.

B. Get the app files

  1. If you received a link to GitHub: open it, select the green Code button, then Download ZIP. If you received a ZIP file, use that.
  2. In File Explorer, right-click the ZIP file › Properties. If you see an Unblock box at the bottom, tick it and select OK. (This lets the app's start scripts run.)
  3. Right-click the ZIP file again › Extract All… Choose a simple folder such as C:\FabricMCPStudio and select Extract.

C. Create the desktop icon

  1. Open the folder you extracted, then open the scripts folder.
  2. Right-click create-shortcut.ps1 › Run with PowerShell. A blue window opens.
  3. The first time, it downloads the app's components (about 150 MB). This takes a few minutes – wait until the window says the shortcut was created, then close it.
  4. You now have a Fabric MCP Studio icon on your desktop.
Alternative without the icon: double-click Start-Studio.cmd in the main app folder. A black window opens – keep it open while you use the app, and close it when you're done.
If Windows says the script is blocked, ask IT to allow it, or open the Start menu, type PowerShell, open it and paste: powershell -ExecutionPolicy Bypass -File C:\FabricMCPStudio\scripts\create-shortcut.ps1 (change the folder if you extracted somewhere else).

Start, stop and update the app

Start

  1. Double-click the Fabric MCP Studio icon on your desktop.
  2. Your browser opens the app at http://127.0.0.1:4870. (This address means "my own computer" – nothing is published on the internet.) Tip: bookmark it.
  3. The very first time, a Disclaimer appears. Read it and select I understand.
Already running? Double-clicking the icon again just reopens the app in your browser – it never starts a second copy.

Stop

Select Shut down at the top right of the app. If a job is still running, wait for it to finish first – shutting down stops it.

Update to a new version

When someone gives you newer app files, replace the old folder (or let IT update it). The app notices and shows a yellow banner at the top: "A newer version is installed – Restart now". Select Restart now; the page reloads by itself after a few seconds. Your project, chats and settings are kept.

Select the version number next to the app name (for example v1.33.26) to see What's new.

Sign in and choose your AI

Sign in to Microsoft Fabric

  1. Select Sign in at the top right.
  2. Choose Sign in with browser (recommended). A Microsoft sign-in page opens – use your work account. If your IT team set up the Azure CLI for you, you can choose Sign in with Azure CLI instead.
  3. When you're signed in, your name and initials appear at the top right. Select them any time to see the account, Switch account or Sign out.

Choose your AI (Copilot)

Copilot uses the AI service your organization already licenses. You set it once.

  1. Select Settings (top right of the map).
  2. In AI provider, select the card your IT team told you to use – most often Azure AI Foundry / Azure OpenAI.
  3. Fill in the fields with the values from IT – for Azure: Endpoint and Deployment name. Keep Authentication on Microsoft Entra ID (recommended), so you don't need a key.
  4. Select Save, then Test. A green message with a short reply means it works.

Decide how Copilot asks for approval

In Settings › Approvals keep Ask every time (recommended). Every change Copilot wants to make then opens a review window first. Auto-approve is only for demos in a test workspace; Read-only lets Copilot answer questions but never change anything.

Run the setup check

Select Check setup at the top. The app tests your sign-in, capacity, AI, connections and Fabric settings.

The app opens on the solution map – a picture of everything you can build, from left (data) to right (sharing). The top row is analytics; the bottom row is real-time (live) data.

Clicking on the map

  • Click a box once to see its details below the map, with buttons such as Open, Let Copilot do it and Open in Fabric.
  • Double-click a box to go straight to its page.
  • Three handy double-clicks: Data source lists the data in your workspace; Semantic model lists your models; the workspace name (at the top of the frame) lists your workspaces.

The four tabs

At the top right of the map: Overview (the map and suggestions), Copilot (the full-size chat), Activity (everything that happened) and Settings. On other pages the map gets smaller; Hide map folds it away.

Jobs that take a while

Longer tasks – loading data, building a report – run in the background. A small card at the bottom right shows the progress. You can keep working meanwhile. Select the card to see the details, or open Activity.

Working with Copilot

Copilot is your assistant inside the app. It can explain your data, answer business questions with your real numbers, and build things for you.

How to talk to Copilot

  • Write as you would to a colleague: "Which product category grew the most last year?"
  • Be specific about what you want built: "Build an executive report with a map, in the Executive Navy theme."
  • Ask "why" and "how": "Why did sales drop in March?", "How do I share this report with my team?"
  • On every page, buttons marked ✦ (for example ✦ Ask Copilot) start a conversation about that page for you.
  • + New starts a fresh conversation; History brings back earlier ones.

Approving changes

When Copilot wants to create or change something in Fabric, a window titled "Copilot wants to make a change" shows exactly what it will do. Read it, then select Approve or Decline. Nothing changes until you approve.

When Copilot suggests a design (a semantic model, a report, a data agent), it shows an Apply suggestions or ✓ Apply button under its answer. Select it to review and build – there's no need to type "yes".

AI can be wrong. Always read Copilot's suggestions before you apply them, and double-check important numbers in Power BI.

Step 1 – Name your environment

Before the app creates anything, tell it what this environment is for. It then names every item clearly, for example Sales_WS_Analytics_PROD = the Sales team's workspace for analytics in production. Anyone can tell from the name what an item is and where it belongs.

  1. Open the Workspace page (double-click the workspace frame on the map, or select Workspace from the Overview).
  2. In What is this environment for?, select one card: Demo or showcase, Proof of concept, Development, Testing, User acceptance, Production, Training or workshop or Personal sandbox.
  3. Type your Business domain – the business area, for example Sales or Finance.
  4. Check the preview on the right (Names the studio will use) and select Use this naming.
Items that already exist keep their names. You can change the naming later with Save naming.

Step 2 – Choose a workspace

Everything the app builds goes into one Fabric workspace. Create a new one, or use one you already have.

Create a new workspace

  1. On the Workspace page, select Create new.
  2. Workspace purpose: a word such as Analytics. The full name is shown below it.
  3. Capacity: pick one from the list. Trial capacities are marked (trial).
  4. Optionally add a Description, then select Create workspace.
The Create workspace button stays grey until you finish Step 1 (naming).

Use an existing workspace

  1. Select Use existing, find the workspace (use the search box) and select it.
  2. Or double-click the workspace name on the map to see every workspace on your capacity, then select Use.
Switching workspace starts the project over in the new workspace. The app asks first, and nothing is deleted – everything you built stays in the old workspace.

Step 3 – Connect your data

Open the Data page. Pick one of three ways to bring in data. Not sure? Start with sample data – it's the fastest way to see the whole app working.

OptionChoose it when…Time
Sample dataYou want to learn or demo the app. Two samples: Contoso Retail (a store chain) and AdventureWorksDW2022 (a bike company).3–8 min
Your databasesYour data is in Azure SQL, SQL Server or PostgreSQL. Fabric keeps a live copy (called mirroring).5–15 min
Existing Fabric dataYour data is already in a Fabric lakehouse, warehouse, mirrored database or SQL database.1 min

Option A – Sample data

  1. Select the Sample data tab.
  2. For Contoso Retail select Load sample. For AdventureWorks select Create in my workspace.
  3. Optional for Contoso Retail: tick Also create a data prep notebook (Python) to get cleaned tables and charts.
  4. Watch the progress card at the bottom right. When it finishes, the Data page shows your tables.

Option B – Your databases

  1. Select the Your databases tab and the type of database.
  2. Fill in the details (server, database) – your database administrator can give them to you.
  3. Choose an existing Fabric connection, or create a new one with the sign-in details.
  4. Select Start mirroring. The page shows each table as it is copied.
Passwords are safe. Database sign-in details go straight to Microsoft Fabric to create a connection. They are never shown to the AI. SQL Server on your company network needs an on-premises data gateway – ask IT.

Option C – Existing Fabric data

  1. Select the Existing Fabric data tab.
  2. Choose the kind of item (Lakehouse, Warehouse, Mirrored database or SQL database) and the workspace.
  3. Select the item. Its tables appear with their row counts.
  4. Select Use in place – the model is built right on that data, nothing is copied. (For lakehouses and warehouses you can choose Create shortcuts in my project lakehouse instead.)

When your data is connected

The top of the Data page summarizes your data: where it lives, how it reaches Fabric, and every table with its rows. Select ✦ Explain my data for a plain-language tour, or Next: semantic model → to continue.

More than one data source

You can add another data source to the same workspace at any time (Add another data source at the bottom of the Data page). Each source keeps its own model, reports and the rest. To switch between them, double-click Data source on the map – nothing changes in Fabric when you switch.

Step 4 – Create or add a semantic model

The semantic model turns tables into business numbers everyone trusts. Open the Semantic model page.

Create a new model from your data

  1. Review the tables (untick any you don't need) and the relationships the app found.
  2. Check the Semantic model name.
  3. Select Create semantic model. With the samples, the app also adds ready-made business measures.

Prefer help? Select ✦ Design it with Copilot. Copilot proposes tables, names, relationships and measures, then shows Apply suggestions to review and create it.

Use a model that already exists

  1. Select ⇄ Switch or add a model (or double-click Semantic model on the map).
  2. Select + Add an existing model, choose the workspace and the model, then Add.
  3. The app reads its tables and measures, and looks in Fabric for the reports and data agents already built on it. They appear on the map and on Reports & apps as Existing report. The app never changes or deletes them.
One model is active at a time. Reports, Copilot's answers, the data agent and the org app use the active model. Switch any time with Use this model – nothing changes in Fabric.

Improve your model with Copilot

Select any of the ✦ buttons on the page, for example ✦ Add business measures from my glossary or ✦ Run a best-practice review. Copilot explains each change and asks for approval.

If the model shows an error – "Check data"

Sometimes data contains duplicate rows, and the model can't answer (you'll see a message such as "has repeated values … one side of a relationship"). Select 🩺 Check and fix the data (or 🩺 Check data in the model bar).

  • The app checks every relationship against the real data and shows Unique or how many extra rows there are.
  • If the extra rows are exact copies in a warehouse, select Remove … duplicate rows. A backup copy is kept first.
  • If it says Model has older rows, select ↻ Reload the model.

Step 5 – Build Power BI reports (with maps)

Open Reports & apps. The bar at the top shows which semantic model the reports are built on.

The fastest way – a recommended report

Recommended for your data suggests reports for different audiences, each with the reasons from your own data.

  1. Read the cards – for example Executive report (for leadership) or Regional report (with a map).
  2. Select Build. The report is created in your workspace in a minute or two.
  3. Or select Customize to change pages or theme first.

What the app found in your model

This card shows what the reports will use: headline numbers (KPIs), time, breakdowns, top-10 lists and the Map line – the places it found, such as Country › State › City.

Design your own report

  1. In Design a Power BI report › Pages, tick the pages you want: Executive summary, Performance drivers, Scorecard, Business rules, Plan vs actual and Map.
  2. Pick a Theme (colors and style).
  3. Check the Report name and select Build report.

Maps

When your data has countries, states, cities, postal codes or latitude/longitude, the app adds a Map page: bubbles sized by your main number, which you can drill from country to state to city, next to the top places. You don't have to do anything special – the app finds the location columns by itself.

Maps use Power BI's Azure Maps visual. If the map shows a message instead of a map, ask your Fabric administrator to turn on the tenant setting "Use Azure Maps visual".

Use your organization's own report templates

Under Your own templates, select Upload template (or drop files on the box). Power BI templates (.pbit), reports (.pbix), zipped Power BI projects, report layouts and themes (.json) are supported. Then select Use template: the app checks which fields match your model and builds the report with your template's look.

Open and share your reports

  • Your reports lists every report. Select Open in Power BI ↗, or ▸ Preview to see the pages here.
  • Org app for your organization › Create app bundles your reports into one app. Then select Publish in Fabric, choose who can see it (the audience) and publish. People don't need access to your workspace.

Step 6 – Ask questions and share

Open Ask & share.

Ask questions about your business

Select any suggested question, or select Ask your own question. Answers use your real measures and respect everyone's permissions and row-level security. The questions are written for your data – your measures, categories and years.

Create a Fabric data agent

A data agent is an AI assistant in Fabric that answers questions about your model – also inside Microsoft 365 Copilot. Select Create data agent, or ✦ Suggest it with Copilot and then ✓ Apply suggestions to review its instructions first.

Put it in Microsoft Teams and Microsoft 365 Copilot

In Microsoft 365 Copilot & Teams, select Install for me to try the agent yourself, or Publish to my organization to submit it for your administrator's approval.

Keep a record

Export › Download project & audit log (JSON) saves what was built and every approval.

Optional steps

These parts add more value but aren't required. Each has its own page and box on the map.

Ontology – your business vocabulary for AI

  1. Open Ontology. In Business glossary, write (or Upload .md/.txt) your terms and rules in plain language, for example "Active customer: a customer with a purchase in the last 90 days". Select Save glossary.
  2. Select ✦ Generate rules with Copilot to turn the glossary into business rules.
  3. Review the entities and rules on the right, then select Deploy ontology.

Planning – budget and forecast

Planning creates next year's budget and a rolling forecast from your actual numbers, and a Plan vs actual report.

  1. Open Planning. Design the plan recommends a plan year and growth – change the growth for any region and select ↻ Apply growth targets to see the effect.
  2. Select Build the plan (about 4 minutes).
  3. Select Build report for the Plan vs actual report, and Create the Fabric plan so planners can refine numbers in planning sheets.
Planning works on a semantic model the app built from your data. If your active model is one you added, the page tells you – switch models or build a new one first.

Real-time – live data

Stream live events shaped like your data, watch them on an auto-refreshing dashboard and get alerts.

  1. Open Real-time and select Set up live data (about 2 minutes).
  2. In Live events, choose how many events per minute and select ▶ Start events. Select ■ Stop when done.
  3. Select Build dashboard, then open it to watch the numbers change every 30 seconds.
  4. Optional: Create alerts (Teams or email) when a business rule breaks, Connect live events to the ontology, or Apply medallion template for Bronze, Silver and Gold layers.

Task flow – organize your workspace

A task flow shows in Fabric how your items fit together. On the Workspace page, in Task flow, pick the flow already in your workspace or one of Fabric's ready-made flows (for example Medallion), check where each item goes, then select Use …. The app keeps it up to date as you add or remove items.

Keep things tidy – remove items and clean up

Remove one item

On the Overview page, Items in this project lists everything the project uses and what depends on it. Select Remove to delete an item in Fabric. The button is disabled while something still uses the item – remove that first (for example the reports before their semantic model). Before anything happens, a window tells you exactly what Remove will do. Items the app didn't create – a model you added, or data you used in place – are only disconnected from the project; the app never deletes them.

Clean up everything

  1. Open Settings › Clean up.
  2. Select Clean up resources. The app lists every item it will delete, and which ones go to the workspace's recycle bin.
  3. Type the workspace name to confirm. Tick Delete the whole workspace only if the app created it and you want it gone.

Start a new project only clears the app's memory on your computer – nothing is deleted in Fabric.

See everything that happened

The Activity tab lists every item created (with links), every job, and every approval or decline.

Safety, privacy and costs

  • You are in control. Copilot asks before every change. Deleting anything always needs your confirmation, and clean-up needs you to type the workspace name.
  • It works with your permissions. The app signs in as you; Fabric security, including row-level security, always applies. It can't see or change more than you can.
  • Your data stays in your organization. Everything the app builds lives in your Fabric tenant. Questions you ask Copilot, and data in its answers, go to the AI service your organization chose.
  • Passwords never reach the AI. Database sign-in details go straight to Fabric.
  • Existing work is protected. Semantic models, reports and data agents you add that already existed are never changed or deleted by the app.
  • Costs. Items run on your organization's Fabric capacity and may use its capacity or incur costs. Clean up what you don't need (chapter 16).
  • Start in a test workspace. Try new things in a Personal sandbox or Development environment before production.
